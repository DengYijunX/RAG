# 项目目标：可用独立语料验证的通用 RAG

用户明确的最终目标：做一个可导入新文档、建立和管理知识库、检索问答及追溯来源的通用 RAG 项目。智能家居售后与企业会计准则只是当前的测试语料，不限定产品的领域、知识库数量或输入数据。

设计参照 LlamaIndex 的摄取与文档身份管理、Haystack 的可组合检索组件、RAGFlow 的知识库 / 文档生命周期。具体出处、当前实现差距及采用取舍见 [成熟项目参考与设计决策](ARCHITECTURE_REFERENCES.md)，不把设计参考等同于已引入相应框架或已有全部功能。

## 产品与测试分离

| 层次 | 应提供的能力 | 现有材料的角色 |
| --- | --- | --- |
| 通用产品 | 文档导入、解析、索引生命周期、检索、生成、引用、知识库隔离 | 不包含固定产品型号或准则名称判断 |
| 可选扩展 | 使用导入元数据做精确定位、版本过滤、结构切片等 | 会计条号路由可作为扩展实例，需要显式启用 |
| 评测 | 固定划分、基线、消融、回答与引用审阅、复现记录 | 售后与会计分别检验不同难点，后续可增加新领域 |
| 演示 | 创建知识库、导入文件、建立索引、问答、查看原文 | 预置语料用于快速体验，同时必须能导入新语料 |

## 当前实现与差距

已验证的能力包括文档加载与切片、OpenAI 兼容模型调用、Chroma 存储、双库隔离、版本化索引切换、引用与原文展示，以及评测工具。

当前 `rag/knowledge.py` 仍通过固定 BASES、仓库实验目录和预生成结构元数据加载两个知识库；页面选项、示例问题、产品型号保护也有领域硬编码。原自定义文档入口虽然允许索引目录，但尚未统一到新的多知识库生命周期、来源展示与隔离机制。因此当前版本是测试语料驱动的原型，尚未达到通用 RAG 的完成标准。

下一步优先消除这些限制，而不是增加更多固定知识库按钮。

## 后续实施顺序

1. 通用知识库注册：持久化知识库 ID、名称、索引配置及可选检索扩展。页面读取注册表，不内置领域列表。
2. 通用文档导入：先覆盖已有加载器支持的 Markdown、TXT、PDF，统一生成文档 ID、来源、内容哈希和可追溯片段；会计 DOCX 转换作为已有数据准备流程保留，额外格式按解析器扩展。
3. 通用索引生命周期：按知识库独立存储，完成全部解析与向量化后发布新版本；失败不覆盖旧索引，语料或模型变化可被检测。
4. 通用问答与来源：对任意已注册知识库查询，返回片段与文档引用；默认流程不猜产品型号或会计版本。领域规则必须明确配置，并能关闭、单独评测。
5. 迁移演示：现有两套语料通过同一导入流程注册。再用一个主题不同、与实现人员调参样本分开的语料检查端到端流程，验证无需修改代码即可接入；这项流程检查不冒充跨领域答案质量评测。
6. 继续质量验收：先开发集审阅和修复，再固定方案与标注，运行保留测试集。两个领域的指标分别报告，不把会计专用路由收益称为通用算法收益。

## 完成标准

- 使用者无需修改 Python 或前端源码，即可创建第三个知识库、导入文档并问答。
- 任意知识库数量均不要求新增 if/else 分支或页面常量。
- 文档来源来自导入流程，不依赖评测 evidence.jsonl、articles.jsonl 或 gold 标签；领域扩展需要的元数据来自解析器或显式输入。
- 不同知识库、索引版本和模型配置之间不会误用数据；失败导入 / 重建能清楚反馈。
- 通用默认检索与每个可选领域扩展分开记录配置、测试和结果。
- 演示、复现命令、架构说明和简历数字均围绕上述通用能力，注明评测语料与适用边界。
