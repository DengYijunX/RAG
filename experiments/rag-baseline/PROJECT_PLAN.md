# 可写入简历的双知识库 RAG 项目

项目定位：一个共享检索框架，服务“智能家居售后”和“多版本会计准则”两个独立知识库。前者验证型号区分、故障澄清和政策冲突；后者验证长文条款定位、版本约束、精确引用和跨条文综合。两个场景分别报告效果，展示方法的适用边界。

## 阶段一：数据与基线

已交付64份文档、201道初始评测题、证据与版本元数据、分组dev/test划分及离线完整性检查。现有加载器可读取两个独立目录。

待完成：人工复核题目，确认元数据和适用版本；修复CLI模块入口及补齐显式依赖声明；实现证据映射后记录原始固定切片/纯向量Top-K的真实指标。模型密钥缺失时，不填写效果数字。

验收：固定语料哈希、模型名称/版本、切片参数、Top-K、问题版本、代码提交；能复现一次完整基线结果。测试集用于评估，调参使用dev。

## 阶段二：逐项实验

实验顺序：原始基线 → 结构切片 → BM25+向量召回及RRF → rerank。结构切片针对FAQ问答边界和会计章节/条文边界分别实现。版本约束单列开关进行对照。

每次只改一个主要因素，保存每题结果和失败案例。不要默认全部组件都带来收益。对同一批题分别报告召回效果、答案依据、耗时与调用成本。

验收：能说明每项改动解决了哪类失败，改善是否来自检索、版本过滤或生成；没有收益的模块保留实验结论，不包装成亮点。

## 阶段三：可靠性与产品行为

实现知识库隔离、结构化引用、信息不足澄清、证据冲突提示和无依据拒答。完善索引增量更新或原子切换、外部API错误处理、目录范围限制和安全的答案渲染。

验收：切换知识库不串数据；知识库更新失败不损坏旧索引；错年份引用可以检测；缺模型密钥、请求失败和空结果有明确响应。保留功能性集成测试与实际错误案例。

## 阶段四：演示和简历证据

交付可复现启动文档、两组有代表性的演示问答、架构图和实验报告。以WeKnora等项目为源码参考时，记录所读提交和文件，说明借鉴思想、实现差异及自己的贡献。

简历可写的已完成事实：整理双场景语料、构建带证据与版本信息的评测草稿、实现DOCX软换行及条号提取并验证内容保真。

尚不能写：线上用户数量、生产稳定性、准确率提升、延迟下降或成本节省。这些必须等真实实验和部署后再填写。

未来表述模板：“面向售后FAQ与多版本会计准则，设计独立知识库及条款级证据标注，构建N条人工复核问题；通过X改造，将指定测试集的Recall@K从A提升至B，P95延迟为C。”N/A/B/C均由后续实测确定。
