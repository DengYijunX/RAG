# 生成侧提示词修复：补上"前提不明应先澄清"

日期：2026-10-10（Asia/Shanghai）。分支 `work`。背景见 [ANSWER_QUALITY_REPORT.md](ANSWER_QUALITY_REPORT.md)。

## 问题

20 题诊断样本的首轮判断发现 **3 处 `missing_clarification`**：

| 题 | 问题 | 首轮回答的行为 |
| --- | --- | --- |
| Q047 | 设置键按不动，应该按多久？ | 直接给 X1 两套步骤，末尾才提"请确认型号" |
| Q051 | 门锁开始滴滴响，是不是快没电了？ | 直接区分两种蜂鸣，未确认型号与节奏 |
| ACC-Q122 | 收到货款就能确认收入吗？ | 直接分版本作答，未询问适用版本与交易类型 |

**根因不在模型，在提示词。** 当时的系统提示词只教了两件事：

```
…问题包含多部分时逐项回答；缺证据的部分明确说"本次检索片段不足以回答"…
```

它教了**逐项回答**、教了**缺证据要承认**，但**完全没提"前提不明该先问"**。模型于是把"型号/版本不明"当成又一个需要逐项展开的条件，条件性作答是这段提示词的直接后果。

## 改动

[rag/kb_service.py](../../../rag/kb_service.py) 中把生成指令提为模块常量 `GENERATION_SYSTEM_PROMPT`（便于测试锁定），并新增一条：

```
若问题缺少关键前提（如未指明产品型号、未指明适用版本或年份），
且不同前提会得出不同结论，应先用一句话说明需要确认什么，再说明各前提下的差异；
不要在没有依据的前提下直接选一个前提作答。
```

措辞是有意的：**先声明需确认什么，再给各前提下的差异**。不要求"只问不答"——用户往往不知道自己该提供什么，纯反问会让回答不可用；要求"先澄明前提"既满足了先澄清的要求，也保留了可用性。

## 效果（20 题诊断样本，同一套检索与索引）

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| 售后 要点完整性满分 | 1 / 5 = 0.20 | **3 / 5 = 0.60** |
| 售后 行为匹配满分 | 8 / 10 = 0.80 | **10 / 10 = 1.00** |
| 售后 引用忠实性满分 | 9 / 9 = 1.00 | 9 / 9 = 1.00 |
| 会计 要点完整性满分 | 3 / 7 = 0.43 | **4 / 7 = 0.57** |
| 会计 行为匹配满分 | 9 / 10 = 0.90 | **10 / 10 = 1.00** |
| 会计 引用忠实性满分 | 8 / 8 = 1.00 | 8 / 8 = 1.00 |
| `missing_clarification` | 3 题 | **0 题** |
| `retrieval_missing` | 5 题 | 5 题（未变） |

**`missing_clarification` 归零**，而那 3 题的回答确实变了：Q047 现在以"需要先确认：你用的是 X1 还是 X2，以及你是想强制重启还是重置 WiFi"开头；ACC-Q122 以"需要先确认：你问的是哪一版收入准则以及具体交易类型"开头。

**`retrieval_missing` 5 题没动**，符合预期——那是检索没给到证据，与生成提示词无关。

## 回归检查

改提示词的风险是让模型到处反问。已核对：

| 题 | 预期行为 | 修复后 |
| --- | --- | --- |
| Q008（换手机恢复控制） | 回答 | 直接作答，未多问 |
| Q055（查订单物流） | 拒答 | 仍说明无法查询，未反问 |
| ACC-Q132（要 2026 版全文） | 拒答 | 仍说明附件无该版本，末尾补充"请确认所需版本/年份"，未编造 |

另外两库的**行为匹配满分率都升到 1.00**，没有出现"该答却反问"的案例。

## 必须一起读的三条限制

1. **样本是 20 题定向诊断选样**，不是随机抽样——**不估计总体准确率**，改善幅度不能外推。
2. **这是一次改动的前后对照**（n=20），且评审由助手与 AI 领队各做一遍。同一份回答两次评审结果不同（例如 Q051 首轮助手记 `1/2/1`、复评记 `na/2/1`；Q055 首轮记 `na/1/2`、复评记 `2/2/2`），**说明单次评审数字有噪声**，本表的分差大于噪声但不能当精确增益。
3. **仍未做人工审阅**，`human_*` 字段为空；`retrieval_missing` 的 5 题仍是检索侧问题，需要切片策略改动。
