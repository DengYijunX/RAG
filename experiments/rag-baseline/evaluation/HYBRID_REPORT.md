# 词法融合与精确定位对照实验

本轮得到一个值得进入下一阶段验证的候选方案：**售后库保留向量检索；会计库仅在问题明确给出准则、年份和单一条号时优先返回完整条文，其他问题沿用向量检索。** 会计开发集平均证据覆盖率从 92.29% 提高到 96.77%，增加 4.48 个百分点；可评分题中未新增覆盖率退步。尚未接入应用，也未完成独立测试集验证。

这是字符证据覆盖率，**不是答案准确率**。开发集题目偏重模板化条号定位，收益集中在这一类任务，不能外推为开放式会计问答全面提升。候选标注仍待领域专家审阅。

## 方法和对照

复用原始 500/50 大块及其 Chroma L2 索引；复用结构实验缓存的查询向量，不新增 Embedding API 调用。检查原始文档、问题、模型配置、索引 ID / 正文 / 来源和缓存问题顺序，保存来源哈希。

检索函数只接收问题文本与向量，不接收题号、类别、目标证据 ID 或预期答案。条文与文档元数据来自完整语料。检索结束后才用候选 gold 计算指标。

| 方案 | 行为 |
| --- | --- |
| 原始基线 | 之前真实运行并保存的 Top-4 结果 |
| 向量回放 | 原始向量索引，使用后续缓存的查询向量重新取 Top-4 |
| RRF 融合 | 原始大块向量 Top-20 与 BM25 Top-20 用 RRF 合并 |
| 元数据路由 + RRF | 从问题解析准则名称 / 编号、年份或产品型号，限定来源再融合；明确条号时优先完整条文 |
| 来源均衡 + RRF | 上一方案基础上，对明确多个产品 / 年份优先保留各来源的最高排名块 |
| 精确定位 + 向量回退 | 仅明确准则、年份与单一条号时优先完整条文；其余使用向量回放 |

BM25 使用中文连续双字和英文数字词，k1=1.5、b=0.75；RRF 常数 60、候选深度 20。词法输入包含文档标题和正文。融合方案最多 4 段、正文预算 2,000 字符，不截断单段；若候选与已有同来源上下文重叠达到 80%，跳过。精确定位段可长于原始 500 字符，但仍受总预算约束；不是靠不受限地增加上下文提高指标。

精确路由解析中文 / 阿拉伯数字条号；准则别名从原文标题生成。未指定版本时不自动认定最新版；多个准则或多个不同条号时，禁用可能产生错误笛卡尔配对的精确定位。明确精确查询却找不到条文时返回空结果，不以其他版本条文替代。对于多个年份中仅部分存在、复杂简称或复杂条号组合，仍需要后续结构化澄清与更完整的解析验证。

## 最终开发集结果

开发集共 128 题，售后 43 / 会计 85；纳入覆盖率的可回答题分别 30 / 67。澄清、拒答题不进入该均值。全部证据覆盖表示一题所有目标证据均达到 80% 字符覆盖阈值。平均上下文字符按各库全部开发集题目计算。

| 知识库 | 方案 | 平均证据覆盖 | 全部证据覆盖 | 平均正文字符 |
| --- | --- | ---: | ---: | ---: |
| 售后 | 原始基线 | 97.22% | 93.33% | 1,645.79 |
| 售后 | 向量回放 / 精确定位回退 | 97.22% | 93.33% | 1,644.65 |
| 售后 | RRF 融合 | 93.89% | 86.67% | 1,703.05 |
| 售后 | 元数据路由 + RRF | 95.56% | 90.00% | 1,680.58 |
| 售后 | 来源均衡 + RRF | 96.39% | 90.00% | 1,680.05 |
| 会计 | 原始基线 | 92.29% | 89.55% | 1,695.99 |
| 会计 | 向量回放 | 92.29% | 89.55% | 1,690.33 |
| 会计 | RRF 融合 | 91.54% | 88.06% | 1,739.54 |
| 会计 | 元数据路由 + RRF | 96.77% | 95.52% | 1,496.93 |

会计精确路由触发 46 题：37 道条号定位、8 道版本比较及 1 道明确指定条号的多证据题。与基线相比，ACC-Q041、ACC-Q059、ACC-Q098、ACC-Q114 改善，其余可评分题覆盖率未退步。

| 会计类别 | 题数 | 原始基线 | 精确定位 + 向量回退 |
| --- | ---: | ---: | ---: |
| 指定条号定位 | 37 | 94.59% | 100.00% |
| 版本比较 | 8 | 93.75% | 100.00% |
| 多证据 | 5 | 56.67% | 66.67% |
| 语义问答 | 16 | 96.88% | 96.88% |
| 计算 | 1 | 100.00% | 100.00% |

多证据的改善仅来自明确要求两个版本第四条的 ACC-Q114，不能说已解决一般多跳推理。会计平均正文字符较历史基线减少约 12.66%，这不等于 Token、费用或时延减少同样比例。

向量回放与历史基线有售后 4 题、会计 10 题的命中顺序或内容变化，但逐题覆盖评分相同。查询向量来自后来一次同模型调用，Chroma 使用近似检索；没有将回放声明为历史查询向量的逐位复现。模型服务和索引差异都可能影响结果，未做随机性或显著性检验。

## 典型回答和失败分析

选择 9 个不同问题、10 个问题 / 方案组合检查真实生成；保留首次生成记录。修复路由后仅 ACC-Q085 的 RRF 上下文变化，新调用 1 次；其余 9 条经问题、模型配置和命中内容核对一致后复用，未重复收费。全轮共 11 次生成，API usage 合计输入 10,152 / 输出 3,681 Token，无金额估算。

| 案例 | 助手对照原文检查的结果 |
| --- | --- |
| ACC-Q041 分部报告第五条 | 补齐条文，回答列出定义及五个考虑因素并引用原文 |
| ACC-Q059 职工薪酬 2014 第二条 | 补齐长条文，回答涵盖四类薪酬及定义并引用原文 |
| ACC-Q098 两版职工薪酬第二条 | 两版证据齐全，回答按版本区分分类与范围；其中养老 / 失业保险归类的延伸解释仍需领域审阅 |
| ACC-Q114 两版收入第四条 | 回答区分风险报酬转移与控制权标准 |
| ACC-Q085 租赁现金流 | 精确定位回退保持原向量证据；修复后的 RRF 也召回对应条文，回答本金及利息为筹资活动现金流出 |
| ACC-Q116 租赁确认与现金流分类 | 仍缺一般确认和现金流条文；回答没有完成现金流部分，并含缺少直接来源支持的一般确认表述 |
| ACC-Q118 收入确认与计量 | 仍偏向知识产权许可特殊规则，缺少一般确认与交易价格条文 |
| Q039 C1 / G2 离线排查 | 来源均衡虽包含两个产品，但 C1 命中 HomeKit 问题，回答错误收窄一般离线排查范围 |
| Q040 四产品 5GHz | 补回 X1，但 C1 核心 WiFi 规格证据仍缺；不能把回答“只有 X2”当作充分有据的完整结论 |

这是选择性定性审阅，不是人工签署的准确率评测。生成可能使用模型自身知识，即使偶然说对，也不能算有检索证据支持。旧路由在 ACC-Q085 返回空上下文时，模型仍作出实质回答，正好说明必须分别检查答案正确性与引用忠实性。最终文件及审阅意见见 `hybrid_case_review.jsonl`、`hybrid_audit.json` 和各运行目录。

## 保留的实验迭代

1. v1：全局 RRF 及广泛元数据路由。会计路由覆盖 95.27%，售后仍退步。
2. v2：根据开发集结果增加精确定位 + 向量回退，达到会计 96.77%。其他条件保持不变。
3. v3：合成回归测试发现不存在的精确条号会回退至普通向量，修为返回空结果。重跑后本开发集指标不变。
4. v4：修复别名解析把“租赁准则……现金流量表”中的后者当作准则名称的问题。明确“某某准则”优先于问题中偶然提及的文档标题。修复后广泛路由也达到 96.77%，未超过较窄方案。

各版完整结果和实际执行脚本均保留，不能把 v1 的程序错误当成混合检索算法的固有缺点。售后 RRF 的语义退步仍存在。没有根据测试集调参，也没有在开发集上扫描大量超参数选最大值；但这些仍是看过开发集后的迭代，需独立测试确认泛化。

## 采用与后续

- 保存实验候选配置 `hybrid_candidate.json`：售后使用原向量检索；会计使用精确定位 + 向量回退。应用源码与默认检索行为尚未切换。
- 下一阶段将候选方案接入可交互的双知识库问答入口，返回版本、条号和可核对的来源片段；未知型号、版本及证据不足应有明确行为。
- 开放式多证据任务需要独立研究问题分解、多路召回及重排；本轮不把它标记完成。
- 完成标注审阅与方案固定后再评测 97 道测试题。简历目前可以写“在会计开发集上，字符证据覆盖率由 92.29% 提升至 96.77%”，必须保留开发集、指标定义和未完成人工准确率评测的边界。
