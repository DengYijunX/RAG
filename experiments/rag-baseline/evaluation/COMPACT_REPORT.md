# 实践六：结构提示压缩与完整输入预算

2026-10-08（北京时间）。固定九题、18 次新生成的对照中，精简结构提示将输入 Token 从 **43,807 降到 20,907，减少 52.3%**。正文和引用顺序未变；章节路径、标题可见性与三种边界状态逐项核验未丢失。但模型仍出现边界误读和无依据的条件总数，不能宣称压缩后质量无损或正式验收通过。

## 从上一步学到什么

上一轮直接把完整审计记录发送给模型，hash、长节 ID、重复祖先路径和字段名占用很多 Token。这一轮把两种输出分开：

```mermaid
flowchart LR
    A[原文结构与已选片段] --> B[完整审计记录：hash / 位置 / 章节树]
    B --> C[模型视图：去重目录 + 短节ID + 片段分块]
    C --> D[完整请求字节上限检查]
    D -->|通过| E[LLM生成与服务端Token计量]
    D -->|超限| F[调用前明确失败]
    E --> G[逐题审阅：完整性 / 引用 / 边界理解]
```

实现：[rag/context_structure.py](../../../rag/context_structure.py)。章节目录每节保存一次，字段为 `[节ID, 父节ID, 可见标题摘录, 识别方式]`；片段块字段为 `[起点, 终点, 所属节ID, 前面有续接内容, 后面还有内容, 本次上下文是否覆盖整节]`。

短 ID 仅在请求内有效，按文档身份隔离；相同标题或重复来源 ID 不会跨文档合并。未知状态保留 null，加粗标题保留启发式标记。标题摘录沿用原来的可见性校验，不从未选原文中补答案。完整审计保留在实践五的可校验快照中。

## 实验条件与预算边界

运行：[20261007T171547Z-9beed06a](compact_runs/20261007T171547Z-9beed06a/manifest.json)（目录时间为 UTC）。计划在调用前提交：[compact_plan.json](compact_plan.json)，运行代码提交 `41db35b`。

| 条件 | 完整结构组 | 精简结构组 |
| --- | --- | --- |
| 九题、正文、顺序、引用 | 相同 | 相同 |
| 原文结构与覆盖状态 | 相同 | 相同 |
| 模型侧格式 | 完整审计 JSON | 去重目录与数组 |
| 系统附加指令 | 原结构字段解释 | 精简字段解释，保留原安全与完整性含义 |
| 完整请求字节上限 | 64,000 | 12,000 |
| 生成 | 9 次重新生成 | 9 次重新生成 |

两组都未触及上限，不发生删减或回退。不同上限没有改变本轮正文，但后续真实请求可能被拒绝，需要独立设计预算内选文策略。整个 messages 的序列化大小包含系统指令、问题、正文和结构附注；**字节上限不等于精确 Token 上限**。当前没有集成该模型的官方 tokenizer，不做伪精确换算。

模型使用已配置的 `deepseek-chat`，与应用相同的 SDK 调用设置；按题交替执行顺序，每组每题一次，不使用历史答案。0 次 Embedding、0 次排序。模型格式与相应解释文字为联合干预，没有隔离纯格式的因果贡献。

## 回答逐题审阅

全部 18 条审阅见 [compact_case_review.jsonl](compact_case_review.jsonl)。审阅者是助手，人工评分为 null；完整性和引用忠实性分开，模糊的“概括”粒度不强判满分。

| 题目 | 完整结构组 | 精简结构组 |
| --- | --- | --- |
| Q008 换手机 | 三要点齐全 | 三要点齐全，更简洁 |
| Q040 四型号网络 | 型号与桥接限制齐全 | 同样齐全 |
| Q043 设置键故障 | 含电量、重启和售后流程 | 同样齐全；两组本轮都未漏排查，不能归功于压缩 |
| ACC-Q041 分部报告 | 定义及五因素齐全 | 同样齐全 |
| ACC-Q059 第二条续段 | 完整引用；但“四类”下面五项并列仍误导 | 明确续段属于第二条，未展开全部定义；概括细度存疑，完整性 null |
| ACC-Q098 版本比较 | 主要差异正确，但补造2006“职工”定义所在位置等，分类组织仍混乱 | 主要差异正确，但把续段标记误读为短期薪酬清单不全，且扩大辞退福利归类 |
| ACC-Q114 收入第四条 | 核心正确，额外声称未显示完整章节标题，与可见正文不符 | 核心正确，没有额外缺失断言 |
| ACC-Q116 租赁 | 三核心要点齐全，有额外范围说明 | 三核心要点齐全，附加列报说明偏长 |
| ACC-Q118 时点与金额 | 提醒列表截断，却猜总数为五项，并使用未经核验的现行措辞 | 同样提醒仅见四项，但仍猜总数五项 |

两个关键失败说明了评测为什么不能只检查字段存在或关键词命中：

1. **片段后面有续段，不等于整节在本次上下文里不完整。** ACC-Q098 第二条在多个已选片段中合起来完整，短期薪酬清单在第一个片段已列完，后续是定义。精简组仍把 `after=true` 当成清单未全。程序正确保留 `complete=true`，不能据此推断模型正确理解。
2. **知道列表不全，不等于知道总共有几项。** ACC-Q118 只展示第五条前四项，元数据未提供总数。两组都说“五项”，虽与完整原文一致，却没有被本次引用支持，仍应扣引用忠实性分。

本轮没有纯边界组，不能重新估计结构提示相对无结构的质量收益。所有题仍是九题开发诊断选样；证据覆盖9/9保持不变，不是答案正确率。97题保留测试未执行。

## 验证与复现

- 45 项应用测试、44 项评测工具测试通过；新增5项覆盖同文档去重、跨文档隔离、未知状态、启发式/祖先关系、输入预算边界与不修改原始记录。
- [自动审计](compact_audit.json) 检查运行提交的代码 hash、全部输出 hash、实际请求与引用不变，独立逐块核对短 ID 映射、祖先路径、标题摘录和三个边界状态；18次输出均正常结束。
- 审计工具首次执行遇到相对路径/绝对路径处理错误，补充路径解析后通过；没有重跑或覆盖模型回答。
- 完整审计快照从计划指向的实践五运行读取，并验证 manifest/output hash；本次不重复保存该2MB快照。

## 接下来转向通用导入

精简格式先作为实验候选，不晋升默认策略。边界误读、猜总数及多部分漏答保留为生成回归案例；不继续只围绕这九题反复调提示。

下一工程步骤是将文档身份、原文位置和结构记录接入独立于评测文件的导入流程：动态创建知识库、导入资料、保存文档/切片映射，再构建隔离索引。用第三种主题资料验收“无需修改源码即可接入”，已有两库作为回归夹具。这样通用性与问答质量各有可执行验收，不把一轮小样本优化写成通用 RAG 已完成。
