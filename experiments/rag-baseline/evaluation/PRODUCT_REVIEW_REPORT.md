# 产品侧人工审阅：会计保留集 59 题

日期：2026-10-11（Asia/上海）。分支 `work`。评分标准见 [QUALITY_RUBRIC.md](QUALITY_RUBRIC.md)。

## 为什么单独做这一次

此前的人工审阅（[HUMAN_REVIEW_REPORT.md](HUMAN_REVIEW_REPORT.md)）走的是**评测脚本**：检索用评测自己的 FAISS 存储，配置由命令行参数给出。本轮后端默认改为 FAISS、并启用了深池重排，**产品路径第一次真正可运行**（`active.json` 首次存在）。因此需要核对的是**产品实际配置下的答案**，而不是评测脚本的答案。

驱动方式见 [product_review.py](product_review.py)：检索与生成走**产品服务**（`KnowledgeBaseService`），只有初审评分借用了评测侧的判定器。产物在 `product_runs/`，与 `quality_runs/` 分开存放。

**这次审阅的配置**（即产品当前配置）：

| 项 | 值 |
| --- | --- |
| 知识库 | 产品注册表里的 `accounting`（59 份文档 / 866 片段） |
| 向量后端 | **faiss**（精确） |
| 切片 | 结构感知，500/50 |
| 检索 | 深池 50 → 专用 rerank 前 20 → 取前 4 |
| 生成 | `deepseek-v4-flash` |

所以：**16 道未满分题里，10 道是检索问题，只有 3 道是答题侧问题。**

## 审阅中修正了两处

**1. 我自己的检查器有漏洞（已修）。** 证据状态原先只问"这段文本在引用里吗"，**没问"来自哪个文件"**。语料里同一准则有多个年份版本，且部分条文**逐字相同**，于是 2014 版的条文被当成 2017 版的，把 ACC-Q045 误报为"证据齐全"。现在 `evidence_status` **同时核对来源文件**，2 题重新归入"检索没给到"。

**2. ACC-Q126 改判 2/2/2。** 助手判行为 1 并记 `missing_clarification`，但该回答**开头就写明**"需要先确认：是否属于非货币性资产交换、是否具有商业实质、换入或换出资产公允价值能否可靠计量、是否涉及补价或多项资产"，与开发集里被判 **2 分**的 Q047/Q051 属同一形态（先说明需确认什么，再给各前提下的内容）。**助手这次与既有标准不一致**，所有者确认改判。

## 与评测路径的结果对比（口径相同，但不可直接相减）

同样 59 题的会计保留集，两条路的自动评分：

| 路径 | 完整性 | 引用忠实性 | 行为匹配 |
| --- | --- | --- | --- |
| 评测脚本（FAISS + 深池重排） | 0.807 | 1.000 | 0.983 |
| **产品路径（FAISS + 深池重排）** | 0.754 | 0.982 | 0.983 |

**差异不应被解读为"产品更差"**：两次运行的 embedding 请求批次划分不同（同一文本在不同批次下向量有极小差异），检索命中有小幅变化；而判定器本身在同一份回答上两次评分可差 1 级。**完整性问题都集中在检索侧的同一批题**（ACC-Q002/Q034/Q035/Q044/Q111/Q112/Q117/Q121 两次都出现），这与上述解释一致。

## 限制

1. 审阅者是**项目所有者，不是独立领域审阅者**（`human_review_meta.reviewer_is_independent = false`）；评分由 AI 领队按标准给出并经所有者确认，而非所有者逐题独立打分。
2. **v1 test 79 题已被观察两轮**，按标准此后不得再用于调参；后续开发需新划分保留样本。
3. 只在开发集与 v1 test 上做，**v2 未跑**（其标注仍是草案）。
4. 产品的**澄清/拒答行为**在 59 题中只有 5 题无要点，样本量很小，行为匹配 1.000 的置信度有限。
5. 未做长时运行与并发验证。
