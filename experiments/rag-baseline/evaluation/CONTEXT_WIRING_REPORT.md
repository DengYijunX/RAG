# 邻段扩展接入产品路径：功能保留、默认关闭，但**否决理由已更正**

日期：2026-10-10（Asia/Shanghai）。分支 `work`。前置：[CONTEXT_EXPANSION_REPORT.md](CONTEXT_EXPANSION_REPORT.md)（检索侧口径）、[ANSWER_QUALITY_REPORT.md](ANSWER_QUALITY_REPORT.md)、[QUALITY_RUBRIC.md](QUALITY_RUBRIC.md)。

> **更正说明**：本报告初版称"半径 1 下模型编造了 2017 年收入准则第四条"，并据此否决开启。**该结论是错的，已撤回**。错误原因与更正后的证据见"更正"一节。功能本身仍默认关闭，但理由不同。

## 接入了什么

| 位置 | 内容 |
| --- | --- |
| [rag/context.py](../../../rag/context.py) | 邻段扩展的产品实现：`NeighbourExpander`、`expand_hits`；按源文档顺序取相邻片段，**不跨越文档边界** |
| [rag/generation.py](../../../rag/generation.py) | 读取已发布 generation 的片段记录，**同时支持两种落盘格式**（产品 `manifest.json` / 基线 `records.jsonl`），并把 `metadata.source`、`metadata.document_id` 提升为顶层字段 |
| [rag/kb_service.py](../../../rag/kb_service.py) | `context_hits()`；`query(..., context_radius=)` |
| [rag/config.py](../../../rag/config.py) | `context_radius`，由 `RAG_CONTEXT_RADIUS` 控制，**默认 0（关闭）** |

**关键设计：扩展放在检索之后，不改检索。** 命中仍是原来那些片段、同样顺序、同样数量，返回的 `id` 仍是被检索到的那个，只替换 `content` 并记录 `expanded_span`。这样检索指标（recall/NDCG）不会被扩展悄悄抬高。评测侧 `neighbour_context.py` 改为复用产品实现，避免两份代码漂移。

过程中修掉两个真实缺陷：

1. **发布产物的格式不兼容**。产品 `build()` 写 `manifest.json`，评测基线写 `records.jsonl`，而发布出的 generation 只有后者，导致扩展在评测索引上每道题都 `FileNotFoundError`。
2. **发布产物缺少 `document_id`**。`citations()` 需要它生成原文链接，但基线把它放在 `metadata` 里，深池重排首次接入时会计题全部 `KeyError: document_id`。现在读取层负责提升，`importer._document_id` 也提为公开的 `document_id_for`（它已有第二个消费者，私有会让实现漂移）。

## 更正：初版的"编造"结论是错的

### 初版说了什么，错在哪

初版依据"ACC-Q114 在半径 1 下写出 2017 年第四条，而模型自称片段只有前三条"，判定为**编造条文**（标准里的阻断缺陷），据此否决开启。

**错误在于把模型的陈述当成了事实**——我没有去核对引用片段本身。核对后：

| 配置 | 引用[2] 长度 | 片段里是否含第四条正文 |
| --- | --- | --- |
| 深度 4（关闭扩展） | 489 | 否 |
| **半径 1（开启扩展）** | **982** | **是**：`### 第四条 企业应当在履行了合同中的履约义务，即在客户取得相关商品控制权时确认收入。` |
| 深度 50 + 重排 | 492 | 是 |

半径 1 时片段**确实包含第四条**，模型是如实引用。

### 那 8 处 `unsupported_claim` 也基本是误判

逐题核对被指"片段里没有"的法条，**实际都在引用片段里**：

| 题 | 评审声称 | 实际 |
| --- | --- | --- |
| ACC-Q114 | "片段[2]仅含总则前三条，未提供第四条" | 第四条出现在引用 [1][2][3][4] |
| ACC-Q118 | "片段[1]并未包含该规则" | 第十四条分摊交易价格在引用 [1] |
| ACC-Q116 | "实质结论未被所引片段支持" | 第十条出现在引用 [1][2][4] |
| ACC-Q041 | "（四）（五）超出片段[1]所附原文" | 第五条出现在引用 [1][3] |

**最直接的证据**：ACC-Q114 在半径 1 下引用完整（2006 与 2017 两条第四条原文都在），评审给 **引用忠实性 0**（"核心结论无依据"）；同样的引用完整度在深池+重排下，评审给 **2**。

**结论：引用忠实性这个维度在长片段下不可靠。** 评审的上下文随引用一起变长（983→1448 字/引用），它在长文本里定位不到某条法条，就报"无依据"。这是**测量假象，不是模型缺陷**。这与 [QUALITY_RUBRIC.md](QUALITY_RUBRIC.md) 早已写明的限制一致——不得用 LLM 自评分代替语义评分。

## 更正后的结论

**1. 邻段扩展没有证据表明它有害**，初版的否决理由不成立。它在检索侧的价值（完整命中率 0.866→0.910）仍然成立。

**2. 但它也没有证据表明对答案有帮助**：完整性 7/9 与不开启的 7/10 在噪声范围内，而这要靠一个对长片段有偏的指标来判断——**当前无法公平评价**。公平评价需要不受长上下文干扰的评分方式（人工审阅，或只把"被引用的那一段"交给评审）。

**3. 深池 + 重排是明确更优的方案**：会计完整性 7/10→9/10、售后 6/9→9/9，引用与行为维持满分，**上下文几乎不变**（383→448、407→441 字，评审可靠性不受影响），代价约 0.8 秒/题。它直接解决了那几题"目标条文没进前 4"的根因——深池把条文捞进候选，重排把它提到前 4。

**4. 因此建议：保持扩展默认关闭，改推荐深度 50 + 重排 20。** 这不是因为扩展有害，而是因为它没有被证明有益，而另一个手段被证明了有益且更便宜。

## 深度上限诊断（决定该不该花重排的钱）

新增 [depth_ceiling.py](depth_ceiling.py)：先测"金标签首次进入排名的深度"，再决定是否值得跑重排。会计 67 题的结果：

| 金标签首次出现的排名 | 题数 |
| --- | --- |
| 前 4 名内 | 62 |
| 5–10 名 | 1（ACC-Q118） |
| 11 名以后 | 0 |
| **任何切片都不带该标签** | **4**（ACC-Q041/Q059/Q073/Q083） |

**那 4 题不是池子不够深**，而是切片把条文切开、没有任何单个切片完整包含它——加深池子与重排对它们无效，根因在切片。这一次诊断避免了一次无用的重排运行。

## 限制

1. 样本是 **20 题定向诊断选样**，不估计总体准确率。
2. **引用忠实性维度在长片段下不可靠**（本轮实测），凡涉及长上下文的结论都需人工复核。
3. 未做人工审阅；`human_*` 为空。
4. 只测半径 1；半径 2 在检索侧已显示会计无额外收益。
5. 深池+重排**尚未接入产品默认路径**，仍待决定。
