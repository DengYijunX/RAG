# 结构切片与父条目展开对照实验

结论：**保留原始 500 字符 / 50 重叠 / Top-4 方案作为当前基线，不将结构切片直接替换到应用。** 加入文档标题、年份与条目标题可以缓解纯结构切片的退步，但两个知识库均未超过基线。上下文缩短不等于答案质量提升。

本报告汇总开发集实验与 9 道有选择偏差的典型问题检查。测试集未运行；题目仍待领域人工审阅。覆盖率是字符证据代理指标，不是答案准确率，也不应写成简历中的“准确率提升”。

## 实验设计

- 两个知识库分别建索引：智能家居 5 份文档、83 个 FAQ；会计 59 份文档、1,859 条条文。两库检索与评测不混用。
- 开发集分别 43 / 85 题，其中可计算检索覆盖率的题目为 30 / 67；澄清与拒答题不进入该均值。
- 原始基线为已保存的真实运行结果，重算评分与旧结果逐题一致。各实验使用相同文档、题目划分、Embedding 模型、L2 距离和 Top-4。模型为 `qwen3.7-text-embedding-flash`，生成模型为 `deepseek-chat`。
- 结构方案以原文 FAQ / 条文为父条目，超过 500 字符时再按原来的 500/50 切分；子块不跨父条目。分别得到 85 / 1,904 个子块。篇章标题和序言不单独索引，因此比较包含文档组织与非条文上下文变化，不是仅改变一个数字参数的实验。
- 父条目展开：检索 Top-4 子块后，按首次命中顺序返回去重后的完整父条目；不根据正确答案选择上下文，也不额外补足到 4 个父条目。
- 标题增强：在子块的 Embedding 输入前加原文已有的文档标题（会计含版本年份）及 FAQ 标题 / 条号；返回给 LLM 的正文不变。它是在观察纯结构方案退步后增加的开发集诊断实验，两轮结果均保留。
- 仅文档原文及其结构元数据参与索引；问题、预期答案与评分标签不参与索引或生成提示词。标题增强轮复用前一轮同模型同问题的查询向量。
- 覆盖率：Top-4 上下文合并后，覆盖某条目标证据至少 80% 的规范化字符才算覆盖该证据；重叠去重，错误文件或版本不计分。先逐题计算目标证据覆盖比例，再在可评分题中求平均。

## 采用决策与下一轮范围

1. 应用保留原方案。本轮形成可复核的负向实验，不将失败改动包装成优化成果。
2. 下一轮在开发集比较“原向量检索 + 词法 / 元数据召回”：从用户问题解析明确的准则号、年份、条号，用文档元数据定位；不从 gold 的 `evidence_ids` 获取路由条件。明确要求多个版本时分别召回，缺少版本时考虑澄清。
3. 针对多产品、多政策和多条文问题增加多路召回与去重，在相同上下文预算下比较覆盖率、回答完整性及 Token；扩大 Top-K 与重排需单独做消融。
4. 提示词与产品流程应区分“本次检索上下文不足”和“知识库不存在”，并为型号、版本不明确的问题提供澄清行为。
5. 待人工审阅候选评测集、固定方案与参数后再运行独立测试集。简历现阶段可以写双知识库建设、可复现评测和失败分析；质量提升数字需待后续实测支持。
